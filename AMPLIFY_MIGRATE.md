# Amplify Gen 1 → Gen 2 Migration Plan

## Why

AWS has put Gen 1 into maintenance mode (critical fixes only from May 2026, end of life May 2027). Gen 2 defines the backend in TypeScript instead of CLI wizard JSON/CloudFormation, is actively developed, and has better Next.js and SSR support if we ever go there.

## What won't change

- The React app code and Amplify JS v6 SDK (already upgraded — both config formats are supported)
- DynamoDB data — AWS's refactor tooling moves the existing tables into the Gen 2 stack without copying or migrating records
- Cognito user pool and existing accounts

## Schema translation

The current `amplify/backend/api/roxana/schema.graphql` maps to Gen 2 as follows. This goes in `amplify/data/resource.ts`.

```ts
import { a, defineData, type ClientSchema } from '@aws-amplify/backend'

const schema = a.schema({
  Discussion: a.model({
    version:      a.integer().required(),
    revision:     a.integer(),
    layout:       a.string().required(),
    goalsSummary: a.string(),
    isPrivate:    a.boolean().required(),
    inviteCode:   a.string(),
    pool:         a.integer().required(),
    sentences:    a.hasMany('Sentence', ['discussionId']),
    userDiscussions: a.hasMany('UserDiscussion', ['discussionId']),
  }).authorization(allow => [allow.publicApiKey()]),

  Sentence: a.model({
    content:      a.string().required(),
    searchable:   a.string(),
    discussionId: a.id(),
    discussion:   a.belongsTo('Discussion', ['discussionId']),
  }).authorization(allow => [allow.publicApiKey()]),

  User: a.model({
    username:     a.string().required(),
    userDiscussions: a.hasMany('UserDiscussion', ['userId']),
  }).identifier(['username'])
    .authorization(allow => [allow.publicApiKey()]),

  UserDiscussion: a.model({
    discussionId: a.id(),
    discussion:   a.belongsTo('Discussion', ['discussionId']),
    userId:       a.id(),
    user:         a.belongsTo('User', ['userId']),
  }).authorization(allow => [allow.publicApiKey()]),
})

export type Schema = ClientSchema<typeof schema>
export const data = defineData({ schema, authorizationModes: { defaultAuthorizationMode: 'apiKey' } })
```

**Notes:**
- The current schema uses `globalAuthRule: { allow: public }` which means everything is public via API key. The Gen 2 translation above preserves that. If you want to tighten auth later (e.g. require Cognito for mutations), do it after migration is stable.
- The custom subscription `onDiscussionById` is hand-written in `src/graphql/custom.js`. In Gen 2 you can add a custom subscription via `a.subscription()` or keep using the hand-written query string — the GraphQL operation itself still works.
- The `@index` secondary indexes (byInviteCode, byPool, byDiscussion, byUser) need to be declared explicitly in Gen 2 using `.secondaryIndexes()` on each model. The generated schema from `ampx generate` should handle this automatically.

## Auth

Current: `input AMPLIFY { globalAuthRule: AuthRule = { allow: public } }` — everything public via API key.

Gen 2 equivalent: `defaultAuthorizationMode: 'apiKey'` in `defineData()`, with `allow.publicApiKey()` on each model. No other changes needed unless tightening auth rules at the same time.

## Frontend config

One line changes in `src/index.tsx`:

```ts
// Remove:
import awsExports from './aws-exports'
Amplify.configure(awsExports)

// Add:
import outputs from '../amplify_outputs.json'
Amplify.configure(outputs)
```

`amplify_outputs.json` is generated by `npx ampx generate outputs` and committed to the repo. Everything else in the app stays the same.

## Migration steps

### Phase 1 — Prepare (no production impact)

1. Install the Gen 2 CLI: `npm install -g @aws-amplify/backend-cli`
2. Run `npx ampx migrate` in the project root — this generates a Gen 2 `amplify/` directory from the existing Gen 1 CloudFormation stack
3. Review the generated `amplify/data/resource.ts` against the schema translation above; correct any discrepancies (especially secondary indexes and the custom subscription)
4. Create a new Git branch: `git checkout -b gen2-migration`

### Phase 2 — Test in sandbox

5. Run `npx ampx sandbox` to deploy a personal cloud sandbox (separate AWS resources, no impact on production)
6. Run `npx ampx generate outputs` to produce `amplify_outputs.json`
7. Update `src/index.tsx` to use `amplify_outputs.json` locally
8. Test the full app against the sandbox: sign in, create discussion, write sentences, verify real-time subscription

### Phase 3 — Parallel production deployment

9. Deploy Gen 2 to a new Amplify Hosting branch (e.g. `gen2`) pointing at the Gen 2 stack — production Gen 1 is untouched
10. Smoke-test the Gen 2 branch end-to-end with real data (note: Gen 2 will have its own empty tables at this stage)
11. Connect Amplify Hosting to the GitHub repo on the `gen2-migration` branch for auto-deploys

### Phase 4 — Data refactor (cut-over)

12. Run the **CloudFormation Stack Refactor** via the AWS Console or `ampx` CLI — this moves the existing Gen 1 DynamoDB tables and Cognito user pool under the Gen 2 stack without copying data. Existing records are preserved.
13. Verify all data is intact in the Gen 2 environment
14. Switch the `tryroxana.com` custom domain to point at the Gen 2 Amplify Hosting branch

### Phase 5 — Cleanup

15. Decommission the Gen 1 Amplify environment
16. Delete `amplify/backend/`, `src/aws-exports.js`, and the old `public/` index.html CRA artifacts if still present
17. Update `CLAUDE.md` to reflect the new backend structure

## Risks

| Risk | Mitigation |
|------|-----------|
| Secondary indexes not migrated correctly | Compare generated schema against current queries in `src/graphql/custom.js`; test each query in sandbox |
| Custom subscription (`onDiscussionById`) | Keep the hand-written GQL string in `src/graphql/custom.js` — it works regardless of Gen 1 vs 2 |
| API key expiry on new Gen 2 API | Set a long expiry (365 days) immediately after sandbox and production deploys |
| CloudFormation refactor failure mid-flight | Test the refactor in a cloned/staging environment first; have a rollback plan (Gen 1 stays up until step 14) |
| `pool` field partitioning | Verify `queryDiscussionsByPool` still works in Gen 2 — the `pool` index needs to be declared as a secondary index in the TypeScript schema |

## Timeline estimate

| Phase | Effort |
|-------|--------|
| Prepare & generate | 1–2 days |
| Sandbox testing | 2–3 days |
| Parallel production deploy | 1 day |
| Data refactor & cut-over | 1 day (plus monitoring) |
| Cleanup | half a day |

**Total: roughly one week of focused work.** The biggest unknown is how cleanly `ampx migrate` generates the secondary indexes and whether the custom subscription needs any adjustment.
